# UI/UX Case Study Portfolio — Toy & Game Swapping App

> A recruiter-friendly case study repository showcasing the end-to-end design process for a mobile toy and game swapping platform.

## 1) Project Background

 I designed a **Toy & Game Swapping App** — a mobile platform that enables users to donate, swap, and discover toys or games within a safe, community-driven environment.

### Problem Statement

Many families accumulate unused toys and games that take up space, yet lack a convenient and trustworthy way to pass them on. Existing options (e.g., marketplace apps, charity drop-offs) often feel impersonal, complicated, or raise safety concerns. Parents, students, and budget-conscious users need a simple, secure platform to give, swap, or find toys — reducing waste while building community trust.

### Target Users

Based on questionnaire research (38 respondents), three primary user groups were identified:

- **Parents with young children (0–10 years)**: Want to declutter old toys and save budget by swapping instead of buying new ones.
- **Donors who value social impact**: Prefer giving unused toys to other families rather than discarding them.
- **Trust-focused community members**: Require verified profiles and transparent reviews before engaging in exchanges.

### Early-Stage Questionnaire Survey

The project began with a **15-question questionnaire survey** distributed online via social media and personal networks (convenience sampling). Key findings from 38 valid responses:

- **81.5%** of respondents were aged 18–34, demonstrating high mobile app usage and digital confidence.
- **50%** described their financial situation as "manageable but requiring careful budgeting" — a key motivation for swapping over buying.
- **57.9%** stored or kept unused toys rather than circulating them, revealing untapped supply.
- **Trust and privacy** were the top concerns: 71.1% valued clear safety policies; 44.7% wanted verified accounts and user reviews.
- Cross-analysis showed younger users (18–34) had higher app confidence (3.8/5 vs 2.9/5 for older users), while experienced platform users prioritized navigation over privacy.

These insights directly informed persona development, user stories, and design decisions throughout the project.

## 4) Design Process (from research to prototype)

This project follows a complete design lifecycle across four phases:

1. **User Research & Data Gathering**
   Conducted a 15-question questionnaire survey with 38 respondents to understand user demographics, digital habits, toy disposal behavior, and trust concerns. Developed four personas (Maria Chen, Emily Zhang, Emily Chen, Alex Joe) with data-backed user stories and functional requirements.

2. **Low-Fidelity Prototyping**
   Translated user stories into wireframes and storyboards. Created a Kanban board with acceptance criteria. Designed three annotated wireframe screens (Safety Dashboard, Quick Item Posting, Home Dashboard) applying Norman's design principles and WCAG guidelines.

3. **High-Fidelity Prototype**
   Built an interactive Figma prototype with 8 key screens: Home, Profile, Messages, Chat, Add Post, Post Detail, Category, and Detail Category. Implemented WCAG accessibility (Perceivable, Operable, Understandable) and conducted individual heuristic evaluations.

4. **Usability Improvements**
   Addressed key usability issues identified through heuristic evaluation:
   - Improved completion status visibility (30% faster post completion)
   - Added validation error feedback (20% reduction in troubleshooting time)
   - Increased tap target sizes to 44×44pt (Apple HIG / WCAG 2.5.5)
   - Standardized "Like" icon across all screens for consistency
